## Demos and visualizations within the explanation

Use `demo` for interactive instruments and precise static figures. `visual` is a compatibility alias using the same builder. Specify the concept, exact geometry, labels, formulas, parameters and interactions in a self-contained brief. The builder does not see the lesson. Application components and styling are supplied automatically; do not request a separate theme or card.

Each artifact should explain one idea. Connect the explanation to its elements and controls. Use interactive demos when changing a value or watching a process helps understanding; use static figures for spatial relationships. Mermaid remains available for simple relationships and flows.

The builder tests execution and inspects its render. On failure, acknowledge the limitation and continue with a textual explanation or request a corrected artifact. A retry creates a new job ID; place its new reference explicitly. Never claim a failed or pending artifact is ready.
